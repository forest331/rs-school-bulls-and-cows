# Design Document: Bulls and Cows

## 1. Структуры данных и алгоритмы

### Состояние игры и история попыток

Состояние игры хранится в объекте `GameState` (`src/core/gameState.ts`):

- **Секрет — строка, а не число.** Позволяет сохранять лидирующие нули (например, `0123`).
- **История — `readonly GuessEntry[]`.** Массив объектов `{ guess, bulls, cows }`. Использование `readonly` защищает от случайной мутации (например, `push`).
- **Обновление через spread:** Каждая попытка добавляет запись иммутабельно через `[...state.history, entry]`.

### Алгоритм `evaluateGuess`

1.  **Быки (Bulls):** `secretChars.filter((char, i) => char === guessChars[i]).length`. Считаем позиционные совпадения.
2.  **Коровы (Cows):** Исключаем бычьи позиции из обоих массивов. Строим мультимножества (словари) и считаем пересечение: `Σ min(countInSecret, countInGuess)`. Это гарантирует, что одна цифра секрета дает не более одного быка или коровы.
3.  **Регистр:** везде используется `toLowerCase()` до сравнения.

### Алгоритм `countPossibleSecrets`

Реализована рекурсивная формула перестановок без повторений: `P(base, length) = base × P(base − 1, length − 1)`. База рекурсии: `P(base, 0) = 1`. Результат мемоизируется в `Map` по ключу `${length}:${base}`.

## 2. Сложность (Big O) — Обоснование для каждой функции

- **`generateSecret` — O(length × base).** На каждом из `length` шагов выбираем случайный индекс и удаляем символ из строки через `slice` (это O(base)). Для `length ≤ 6, base ≤ 16` — константное время.
- **`evaluateGuess` — O(length).** Два прохода по массиву длины `length`: сначала `filter` для быков, затем `reduce` по уникальным символам. Уникальных символов не больше 16 (алфавит hex), поэтому фактически O(length · 16) = O(length).
- **`isValidGuess` — O(length).** Проверка длины O(1), затем `every` по символам с O(1) lookup в `Set` валидатора, затем `new Set` для уникальности — O(length).
- **`countPossibleSecrets` — O(length) без мемоизации, O(1) с мемоизацией.** Рекурсия глубины `length`, на каждом шаге одно умножение. Мемоизация через `Map` делает повторные вызовы O(1).

## 3. Принципы чистого кода (с указанием файлов)

- **Чистые функции:** Вся логика в папке `src/core/` не зависит от DOM и глобального состояния. Функции детерминированы, без побочных эффектов.
- **Функции высшего порядка (HOF):** Функция `evaluateGuess` (`src/core/evaluateGuess.ts`) использует методы `filter`, `reduce`, `map` вместо ручных циклов `for`/`while`. В `gameState.ts` история обновляется через `[...history]`, а не через `push`.
- **Каррирование:** Фабрика `createDigitValidator` (`src/core/createDigitValidator.ts`) возвращает предикат `(char) => boolean`. Применяется в `isValidGuess.ts` и в `gameScreen.ts` для фильтрации ввода в реальном времени.
- **Мемоизация:** Функция `countPossibleSecrets` (`src/core/countPossibleSecrets.ts`) кэширует результаты в `Map`.
- **Рекурсия:** `countPossibleSecrets` реализован рекурсивно с базой `length === 0`.
- **Иммутабельность:** Функции `startGame`, `addGuess`, `resetGame` в `gameState.ts` возвращают новые объекты, не мутируя входные данные.
- **Инъекция зависимостей:** `generateSecret` принимает `random`, `startGame`/`addGuess` — `random`/`now`. Это позволяет тестировать их с детерминированными значениями.
- **Разделение ответственности:** `src/core/` — чистая логика; `src/ui/` — рендеринг; `src/ui/app.ts` — оркестрация. UI-модули не содержат игровой логики.
